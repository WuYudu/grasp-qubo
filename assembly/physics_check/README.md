# 物理校验：把计划放到 MuJoCo 里走一遍

这个目录回答一个问题：**抽象层说"这步能放"，物理层真的能放吗。**

前面所有实验都在我自己写的世界里跑（矩形、几何相交、规格约定）。那套模型有两条规则是我定的，
不是物理给的：槽口只认同类零件、放错就报废。这里用 MuJoCo 4.0.1 把同样的零件和槽口做成刚体，
看九种组合在重力下到底会怎样。

## 一、九格落体矩阵

槽口内宽 = 零件宽（零间隙）与槽口内宽 = 零件宽 + 4 mm 两种设置，零件从 3 cm 高处自由落下，沉降后读落位高度。
0.0349 表示落到槽底，0.0685 表示卡在槽口。

| 零件 | 槽口 | 零间隙 | 留 4 mm | 物理可放 | 我们模型的判定 |
|---|---|---|---|---|---|
| A 0.080 | A 0.084 | 卡住 0.0685 | 落底 0.0349 | 是 | 匹配 |
| A 0.080 | B 0.124 | 落底 0.0349 | 落底 0.0349 | 是 | 报废 |
| A 0.080 | C 0.164 | 落底 0.0349 | 落底 0.0349 | 是 | 报废 |
| B 0.120 | A 0.084 | 卡住 | 卡住 0.0850 | 否 | 报废 |
| B 0.120 | B 0.124 | 卡住 0.0648 | 落底 0.0349 | 是 | 匹配 |
| B 0.120 | C 0.164 | 落底 | 落底 0.0349 | 是 | 报废 |
| C 0.160 | A 0.084 | 卡住 | 卡住 0.0850 | 否 | 报废 |
| C 0.160 | B 0.124 | 卡住 | 卡住 0.0850 | 否 | 报废 |
| C 0.160 | C 0.164 | 卡住 0.0618 | 落底 0.0349 | 是 | 匹配 |

读法：物理的判据是"零件宽不超过槽口宽"，九行完全对得上。模型的判据是"种类相同"，更严一半。
A→B、A→C、B→C 这三组物理上轻松落底，模型却判报废。

## 二、真计划执行

从 `assembly_qubo` 里取两条 `risk` 后端产出的计划，在 MuJoCo 里逐步执行：抬起、平移对位、下放、释放沉降 1.2 s。

| 计划 | 步数 | 物理成功 | 落位高度 | 水平偏差 |
|---|---|---|---|---|
| seed 0（同类配对） | 6 | 6 | 0.0349 | 0.0000 |
| seed 1（同类配对） | 6 | 6 | 0.0349 | 0.0000 |
| 故意跨类 A→B | 2 | 2 | 0.0349 | 0.0000 |

12 步全部落到槽底。跨类两件也成功——再次说明"放错就报废"是约定。

## 三、这条约定影响有多大

把判据从"种类相同"换成长宽几何（`pw <= slot_w`），四后端 × h=1..4 × 3 种子各跑一遍：

| h | 保守贪心 | 风险感知 | 整数规划 | 退火 |
|---|---|---|---|---|
| 1 | 0.767 / **1.967** | 0.800 / 1.667 | 0.767 / 1.700 | 0.233 / 0.467 |
| 2 | 0.800 / 1.967 | **0.800 / 2.000** | 0.800 / 1.700 | 0.233 / 0.800 |
| 3 | 0.800 / **1.967** | 0.333 / 2.000 | 0.567 / 1.367 | 0.033 / 0.233 |
| 4 | **0.800 / 1.667** | 0.100 / 0.933 | 0.100 / 1.467 | −0.167 / 0.000 |

每格是"种类判据 / 几何判据"。两件事没变：承诺长度越过观测边界后，利用陈旧信息的后端仍然从加分变扣分；
保守贪心仍然是最稳的一条平线；退火在两种判据下都是最差。

变化的是绝对分数（普遍抬高约 1.2）和报废率（例：退火 0.10–0.17 → 0.04–0.14）。唯一被改动的排序在 h=2：
几何判据下风险感知 2.000 略高于保守贪心 1.967，差 0.033，三个种子的方差盖得住，不写成结论。

## 四、限制

- 搬运是运动学设置位姿，没有夹持力、没有碰撞过程、没有夹爪开合。它只能证明末态对，不能证明过程对。
- 零件是矩形、槽口是四面墙，没有倒角、摩擦系数取默认值。
- 没有相机与点云，感知环节仍然是抽象层的假设。

## 五、跑起来

```
python slot_test.py      # 九格落体，零间隙
python slot_test2.py     # 九格落体，留 4 mm
python plan_in_mujoco.py # 真计划执行
```

依赖 MuJoCo 4.0.1（`pip install --target <libs> mujoco==4.0.1`，装完删掉 libs 里的 numpy 以免盖掉系统版本），
并且 `PYTHONPATH` 要包含 `assembly_qubo/src`（计划来自那里）。
